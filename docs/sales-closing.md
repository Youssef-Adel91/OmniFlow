# مساعد إغلاق الصفقات (Sales Closing)

**الحالة:** مبني ومُختبر بالـ mocks وقاعدة بيانات محلية فقط — لم يُجرَّب على Meta/WhatsApp حقيقيين، ولا مع نموذج لغوي حقيقي. مقفول افتراضيًا.

## التفعيل (قفلان)
1. منصّة: `FEATURE_SALES_CLOSING=true` في بيئة التشغيل (الافتراضي false). عند false تردّ واجهات `/api/v1/deals/*` بـ 404 ولا يعمل أي من المنطق.
2. مكتب: `tenant_preferences.sales.enabled = true` (الافتراضي false). المتابعات التلقائية قفل ثالث: `sales.followup_enabled`.

## كيف يعمل
كل رسالة عميل تمر على `src/sales/hook.py` قبل النموذج:

| المسار | ما يحدث | يصل للنموذج؟ |
|---|---|---|
| إيقاف الرسائل | يُسجَّل `opt_out_at` وتُلغى المتابعات، ردّ ثابت | لا |
| حقن تعليمات / طلب بيانات عملاء آخرين | ردّ ثابت مهذب | لا |
| شكوى | ردّ ثابت + تحويل لموظف | لا |
| تفاوض على السعر | ردّ ثابت + تحويل لموظف (لا خصومات من النموذج) | لا |
| حجز معاينة | حوار مواعيد (Redis `sales:booking:*`) ثم موعد `appointments` | لا |
| حديث عادي | تأهيل (ميزانية/حي/غرف/نوع/تمويل/استعجال) + تقييم Hot/Warm/Cold + مطابقة عقارات `VERIFIED_ACTIVE` فقط → تُضاف كسياق للنموذج مع قواعد صارمة | نعم |

التقييم والاستخراج قواعد (regex) بلا نموذج: `qualification.py`. المطابقة (`matcher.py`) بأربع مستويات: مطابق تمامًا ← بدون عدد الغرف ← أحياء أخرى ضمن الميزانية ← أعلى من الميزانية بحد 15% (مع ملاحظة صريحة). نص العقار الذي يشبه تعليمات يُحذف.

## الصفقات
جدول `deals` (new → qualified → viewing → negotiation → won/lost). صفقة مفتوحة واحدة لكل عميل (فهرس فريد جزئي). المساعد يقدّم المرحلة للأمام فقط ولا يغلق صفقة أبدًا؛ الإغلاق (won / lost + سبب إلزامي) من الموظف عبر `PATCH /api/v1/deals/{id}`. `reached_stage` يحفظ أبعد مرحلة وصلتها الصفقة لتقرير التحويل `GET /api/v1/deals/report`.

## المتابعات والتذكيرات
Celery beat كل 5 دقائق (`omniflow.sales_followups`): خطوات بتأخيرات `followup_delays_hours` (افتراضي 2/20/72 ساعة)، دورتان كحد أقصى لكل عميل، تتوقف عند ردّ العميل أو الإيقاف أو إغلاق الصفقة. داخل نافذة 24 ساعة: نص عادي؛ خارجها: قالب WhatsApp معتمد إن وُجد (`whatsapp_followup_template`)، وإلا تُتخطى الخطوة. تذكير المعاينة قبل الموعد بـ `reminder_hours_before`؛ إن تعذّر الإرسال للعميل يُنبَّه الموظف.

## الاختبارات
- `tests/test_sales_pure.py` (بدون قاعدة بيانات)، `tests/test_sales_golden.py` (45 محادثة بأربع لهجات: توجيه 100% + فهم + أمان + حقن في وصف العقار)، `tests/test_sales_db.py` (Postgres+RLS: المطابقة، المسار، المتابعات، العزل بين المكاتب).
- غير مُختبر: ردود النموذج الحقيقي (يحتاج مفتاحًا؛ يُشغَّل لاحقًا بـ `scripts/eval_bot.py`)، الإرسال الفعلي عبر Meta.

## ما ينقص
واجهة Kanban وإعدادات المبيعات وملخص التسليم في الـ inbox (الـ API جاهز: `/deals/board`, `/deals/by-conversation/{id}`).
