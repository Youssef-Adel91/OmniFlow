# Exact, pinned dependency versions — item 19 of the launch-readiness checklist.
# pyproject.toml keeps loose ">=" bounds for local dev flexibility; this file
# is what the Docker image actually installs, so a build today and a build
# next year produce the identical dependency graph. Regenerate with:
#   pip freeze | sort > requirements-lock.txt
# then remove: the local editable package itself, Windows-only transitive
# packages that don't exist on Linux (pywin32, win32_setctime — pulled in on
# a Windows dev machine, would break the Linux image build), dev-only tools
# (pytest/ruff/black/mypy/bandit/safety/pymupdf/pdfminer.six/watchfiles —
# used for local testing and the pdf_builder self-check, not runtime code),
# and fpdf2 (an unused leftover from before the PDF pipeline switched to
# WeasyPrint — see ai_workers/vault_worker/pdf_builder.py's docstring).
# torch is intentionally NOT pinned here: the Dockerfile installs a specific
# CPU-only wheel from a separate index before this file is installed, so
# pip's normal resolver never touches it.
